Foundations

Agent Engineering란 무엇인가

🧠
Reasoning
LLM이 목표를 분해하고 단계별 계획(Chain-of-Thought)을 생성. 복잡한 분석 문제를 하위 작업으로 쪼갠다.
🔧
Tool Use
SQL 실행, Python 코드 실행, API 호출, 파일 I/O 등 외부 도구를 LLM이 직접 호출하고 결과를 해석.
🔁
Feedback Loop
실행 결과를 관찰(Observe)하고 계획을 수정(Reflect)하는 ReAct 패턴으로 자기교정 루프 형성.
# ReAct 패턴의 핵심 사이클
while not_done(goal):
    thought = llm.reason(context)       # Think
    action = llm.decide_tool(thought)  # Act
    obs    = tools.execute(action)      # Observe
    context.update(obs)              # Reflect
Transformation

에이전트가 바꾸는 데이터 분석

Before · 전통적 분석

  • —분석가가 직접 SQL 작성 → 결과 해석 반복
  • —각 단계마다 수동 검토 및 코드 수정
  • —도메인 지식과 코딩 능력을 동시에 요구
  • —재현 가능하지만 확장성에 한계

After · Agent-Driven 분석

  • →자연어 질문 → 에이전트가 쿼리 생성·실행
  • →이상값 감지 시 자동으로 가설 검증 루프
  • →비개발자도 복잡한 분석 파이프라인 운용
  • →동시 다수 에이전트로 병렬 분석 스케일링

Challenges

해결해야 할 과제들

01  Hallucination in Analysis
LLM이 존재하지 않는 통계값이나 잘못된 인과관계를 확신 있게 제시. Critic Agent + 그라운드 트루스 검증 레이어 필수.
02  Cost & Latency
복잡한 분석에서 에이전트 루프가 수십 회 반복되며 토큰 비용 폭증. Caching · 경량 모델 라우팅 · 루프 상한(max_iter) 설계 필요.
03  Data Privacy & Governance
PII 데이터가 LLM 컨텍스트에 노출될 위험. 데이터 마스킹, 온프레미스 LLM, 감사 로그 설계가 선행되어야 한다.
04  Observability
에이전트 내부 추론 과정이 블랙박스화되어 디버깅이 어렵다. Trace ID 기반 LLM Observability(LangSmith, Arize) 도입이 필수.
